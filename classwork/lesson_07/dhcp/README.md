# Протокол DHCP

## Назначение DHCP

Для работы в IP-сети каждому сетевому интерфейсу необходимо назначить IP-адрес и другие параметры TCP/IP: маску подсети, адрес маршрутизатора по умолчанию, DNS-сервер и другие настройки.

**DHCP (Dynamic Host Configuration Protocol)** — протокол динамического конфигурирования хостов. Он автоматизирует настройку сетевых интерфейсов и централизованно распределяет IP-адреса, что помогает избежать их дублирования.

## Предшественники DHCP

Первым использовался **RARP (Reverse Address Resolution Protocol)**. Клиент отправлял широковещательный запрос, а сервер по MAC-адресу находил соответствующий IP-адрес.

Недостатки RARP:
- сервер требовался в каждом сегменте локальной сети;
- MAC-адреса необходимо было регистрировать вручную;
- нельзя было передавать клиенту дополнительные параметры.

Затем появился **BOOTP (Bootstrap Protocol)**. Он позволял передавать не только IP-адрес, но и дополнительную информацию, например адрес TFTP-сервера и имя загрузочного файла. BOOTP также поддерживал relay, благодаря чему один сервер мог обслуживать несколько сетей.

DHCP стал дальнейшим развитием BOOTP.

## Принцип работы DHCP

DHCP работает по модели **клиент — сервер**. При запуске DHCP-клиент отправляет широковещательный запрос. DHCP-сервер отвечает и передаёт клиенту IP-адрес и необходимые параметры сети.

DHCP-сервер может использовать три режима:
1. ручное назначение статических адресов;
2. автоматическое назначение статических адресов;
3. автоматическое распределение динамических адресов.

### Ручное назначение

Администратор заранее связывает определённый IP-адрес с конкретным клиентом. При обращении этот клиент всегда получает один и тот же адрес.

### Автоматическое статическое назначение

Сервер самостоятельно выбирает клиенту адрес из доступного пула. После первого назначения этот адрес закрепляется за клиентом постоянно.

### Динамическое назначение

IP-адрес выдаётся клиенту на ограниченное время — **срок аренды**. После отключения клиента адрес может быть освобождён и позже выдан другому устройству.

## Пул адресов и срок аренды

Основные параметры DHCP-сервера:
- **пул адресов** — диапазон IP-адресов, которые сервер может выдавать клиентам;
- **срок аренды** — время, в течение которого клиент может использовать полученный IP-адрес.

Срок аренды выбирается в зависимости от условий работы сети. В сети с часто меняющимися клиентами он может быть небольшим, а в постоянной корпоративной сети — несколько дней или недель.

## DHCP Relay

Клиенты отправляют широковещательные запросы. Если DHCP-сервер находится в другой сети, используется **DHCP Relay (связной DHCP-агент)**.

Relay принимает запрос клиента и пересылает его DHCP-серверу в другой сети. Благодаря этому один DHCP-сервер может обслуживать несколько разных сетей.

## Алгоритм получения IP-адреса

Обмен между клиентом и сервером проходит следующим образом:

1. Клиент отправляет широковещательное сообщение поиска DHCP-сервера.
2. DHCP-серверы получают запрос и отправляют свои предложения с IP-адресом и параметрами сети.
3. Клиент выбирает одно из предложений и отправляет широковещательный запрос, указывая выбранный сервер.
4. Выбранный DHCP-сервер подтверждает выдачу IP-адреса и параметры аренды.
5. Клиент получает подтверждение и начинает использовать полученную конфигурацию.

Остальные DHCP-серверы отменяют свои предложения и возвращают предложенные адреса обратно в свои пулы.

## Продление аренды

До окончания срока аренды клиент пытается продлить её у DHCP-сервера. Если сервер недоступен, клиент повторяет попытки и при необходимости обращается к другому серверу. Если получить новую конфигурацию не удаётся, клиент теряет выданные параметры.

## Статические и динамические адреса

Динамические адреса удобны для обычных клиентских компьютеров, так как позволяют автоматически использовать адреса из общего пула.

Статические IP-адреса обычно назначают устройствам, адрес которых должен оставаться постоянным:
- маршрутизаторам;
- серверам;
- принтерам;
- другим сетевым устройствам, используемым для управления и мониторинга.

Постоянный адрес упрощает доступ к устройству, работу DNS, мониторинг и фильтрацию сетевого трафика.

## Вывод

DHCP автоматизирует настройку TCP/IP и распределение IP-адресов. Использование пула адресов и аренды уменьшает объём ручной работы администратора и позволяет эффективно использовать доступное адресное пространство. DHCP Relay позволяет одному серверу обслуживать клиентов из нескольких сетей.
