# HTTP и клиент-серверная модель

Работа по заданию «комп.docx».

## 1. Определения

**HTTP** (Hypertext Transfer Protocol, протокол передачи гипертекста) — протокол прикладного уровня, по которому клиент отправляет запрос, а сервер возвращает ответ. Его используют веб-страницы и API. Запрос содержит метод, адрес ресурса, заголовки и иногда тело; ответ содержит статус, заголовки и иногда тело.

**HTTPS** — HTTP через защищённое соединение TLS. TLS шифрует передаваемые данные, помогает проверить подлинность сервера по сертификату и обнаружить изменение данных в пути. Обычный HTTP сам по себе такого шифрования не обеспечивает.

**Клиент-серверная модель** — способ взаимодействия, при котором клиент инициирует запрос к сервису, а сервер принимает его, обрабатывает и отправляет ответ. Например, браузер запрашивает страницу у веб-сервера.

**Идемпотентность** — свойство операции, при котором повторное выполнение с теми же параметрами даёт тот же конечный результат для состояния сервера, что и однократное выполнение. Например, повторный `DELETE` не должен удалять что-то ещё, хотя коды ответов первого и повторного запроса могут отличаться. Метод `POST` обычно не является идемпотентным.

## 2. Разбор запроса и ответа

Исходный запрос из задания:

```http
POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Length: 58

{"name": "Иван", "email": "ivan@mail.com"}
```

1. Метод — `POST`, обычно используется для создания ресурса или запуска обработки данных.
2. Путь (endpoint) — `/api/users`.
3. Версия протокола — `HTTP/1.1`.
4. `Content-Type: application/json` сообщает серверу, что тело запроса записано в формате JSON.
5. `Authorization: Bearer ...` передаёт токен доступа. Сервер проверяет его и решает, разрешена ли операция. По одному приведённому префиксу нельзя судить, действителен ли токен.
6. Тело находится после пустой строки, отделяющей заголовки: `{"name": "Иван", "email": "ivan@mail.com"}`.

**Ошибка в исходном примере:** это тело занимает 46 байт в UTF-8, поскольку кириллические буквы кодируются несколькими байтами. `Content-Length: 58` не соответствует телу. При передаче ровно этих байтов нужно указать `Content-Length: 46` (или доверить подсчёт HTTP-клиенту).

Исходный ответ:

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/users/42

{"id": 42, "name": "Иван", "email": "ivan@mail.com"}
```

1. `201 Created` означает, что сервер успешно создал ресурс.
2. `Location: /api/users/42` указывает адрес созданного пользователя. Это относительный путь на том же сервере.
3. Тело содержит JSON с идентификатором `42`, именем и адресом почты созданного пользователя.

## 3. Составленные HTTP-запросы

Предположение: API товаров использует коллекцию `/api/products` и адрес отдельного товара `/api/products/{id}`. Точное имя пути зависит от реализации API.

### Получить список всех товаров

```http
GET /api/products HTTP/1.1
Host: example.com
Accept: application/json
```

### Создать товар «Ноутбук» с ценой 50000

```http
POST /api/products HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 39

{"name":"Ноутбук","price":50000}
```

### Удалить товар с id 7

```http
DELETE /api/products/7 HTTP/1.1
Host: example.com
```

### Изменить цену товара с id 3 на 45000

`PATCH` меняет указанное поле и не требует передавать весь объект:

```http
PATCH /api/products/3 HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 15

{"price":45000}
```

Длины тел `39` и `15` указаны в байтах UTF-8 для точной записи JSON из примеров.
